# Історія версій AniTube для Lampa

Номер версії позначає окрему ітерацію. Наступна ітерація після 1.8.10 отримує 1.8.11; не перевикористовувати номер завершеної ітерації. Зберігати попередній код перед новими змінами й додавати запис сюди. Публікація бети та перенесення в основний — окремі статуси, номер локального файла не означає, що його вже опубліковано.

## 2.0.0 — 04.11.2026 — локальний кандидат, не опубліковано (за рішенням користувача номер 2.0.0 замість 1.8.20: з цієї версії відштовхуємось далі)

- Збережено 1.8.19 у `dev/archive/2026-11-04/1.8.19/`.
- Нове: **стеження за аніме на AniTube**. Зірочка на картці Lampa (сіра — не стежу, зелена — стежу) і чип «Стежити/Стежу» на екрані плагіна (лише для джерела AniTube). Зірочка на картці без відомого тайтлу відкриває екран плагіна й додає стеження, щойно тайтл знайдено.
- Власна вкладка **AniTube** у дзвіночку Lampa (`Lampa.Notice.addClass` + `Lampa.NoticeClassLampa`, окрема база `anitube_notice` на цьому пристрої). Кількість непрочитаних лічить дзвіночок Lampa; відкриття вкладки позначає прочитаним, як у самої Lampa. Клік по сповіщенню відкриває екран плагіна саме на стеженій сторінці AniTube. Окремого повідомлення-спливайки нема; вона лишилась лише запасним варіантом для Lampa без цих класів.
- Режими: «Будь-що / Субтитри / Озвучення» (типовий у налаштуваннях, змінюється для кожного тайтла у списку). Сповіщення: назва, «Субтитри · команда» або «Озвучення · команда», «Серія N» або «Серії N–M», «Остання», якщо відомо загальне число.
- Без повторів: рахується найбільша кількість серій за видом (субтитри/озвучення) серед підтримуваних плеєрів (Ashdi, Moon). Друга команда з тією самою серією нічого не додає. Ідентифікатор сповіщення `anitube:<tmdb>:<вид>:<остання серія>`: навіть якщо список стеження втратить пам'ять, дзвіночок не додасть те саме вдруге. Перша перевірка лише запам'ятовує наявне. Сповіщення, яке не вдалося зберегти, повторюється наступного разу.
- Перевірка: через 8 с після готовності Lampa і далі кожні 30 хв перевіряються лише тайтли, яким пора (раз на 6 год, невдала спроба — через годину), по черзі з паузою 2,5 с, не більше 15 за запуск. Кожна перевірка це один запит плейлиста AniTube (Android напряму, ТВ через наш Worker; нових маршрутів не потрібно, платного нічого нема).
- «Мої стеження»: чип «Стеження N» на екрані плагіна і кнопка в Налаштування → AniTube. Для кожного тайтла показує скільки серій субтитрів/озвучення вже було; можна відкрити, змінити режим чи прибрати. Список лишається на пристрої (`anitube_follow`, без синхронізації з акаунтом).
- Список «Джерело» впорядковано заголовками: «Аніме (укр)» (AniTube, AnimeOn), «Фільми, серіали, дорами (укр)» (UAFilms, UAflix, UA Serials, Makhno, DoramaUA), «Російські» (AniLibria, лише за перемикачем). Нове джерело додається одним рядком під потрібним заголовком (`sourceMenu`). Порядок автопошуку не змінився. VeoVeo не додано: без відповідності TMDB → номер у VeoVeo й без чужого токена його не підключити; KinoHub не знайдено на пристрої користувача, відкладено.
- Не робилось: окреме зняття відмітки «переглянуто» по серіях (дзвіночок Lampa очищується цілком при відкритті вкладки), фільтр за конкретною командою, push на телефон.
- Перевірки: `node dev/test-follow.mjs` (справжній плейлист сезону 2 «Чорної конюшини», `dev/fixtures/anitube-6088-playlist.json`), усі чинні регресії проходять, стенд показує чип. Не перевірено: вигляд зірочки на картці, дзвіночок і пульт на Samsung/LG.

## 1.8.16 — 03.11.2026 — локальний кандидат, не опубліковано

- Відгук користувача про дуже повільний запуск та fatal manifest error стосується Ashdi в AniTube і AnimeOn. Повернуто коротке повідомлення фактичної версії/серії одразу після ОК за прямим проханням користувача. Статусів успіху/готовності немає.

Метадані якості перед запуском очікуються не більш ніж 1,5 секунди; за їх відсутності запускається вихідний мастер. Той самий ліміт метаданих застосовано до наступної серії. Фонова черга нових перевірок призупиняється під час запуску/перегляду.
- Для Ashdi на Tizen/webOS явно передається `hls_type: native`, без глобальної зміни налаштувань. Moon зберігає програмний режим. - Новіша команда ОК перемагає стару відповідь; зміна джерела/тайтлу та закриття скасовують право старого запиту запускати плеєр. Невдале оновлення адреси не може запустити застарілу кешовану адресу.
- Нагляд за початковими canplay/fatal/timeout працює також для Ashdi, з AT-P3/AT-P4 і читабельною помилкою маніфесту. Не обіцяти встановлення причини кожного стороннього manifest error без конкретного потоку.
